# Общая картина установки

## Две программы
1. **Служба `ps4installerd`** — payload (ELF), который запускается с правами GoldHEN. Она одна умеет вызывать системную
   установку PKG. Слушает HTTP на порту **8284** (все интерфейсы). Код: `src/`.
2. **Приложение «PS4 Store»** — обычное PKG-приложение с интерфейсом (1920x1080, управление геймпадом). Оно **само ничего не
   устанавливает**: показывает список игр, спрашивает подтверждение и просит службу по HTTP (`127.0.0.1:8284`).
   Код: `pkg/src/`.

Почему так: приложению из песочницы недоступны системные вызовы установки, а payload под GoldHEN доступны.
Приложение при запуске само отправляет службу на консоль (см. [APP_AND_SERVICE_LIFECYCLE.md](APP_AND_SERVICE_LIFECYCLE.md)).

## Путь одного PKG
```
файл .pkg на флешке (/mnt/usbN/...) или в /data/pkg/...
   │  1. служба сканирует папки (scan_packages), читает заголовок и param.sfo       → GET /scan
   ▼
приложение группирует файлы по Title ID в «игры» (игра + патчи + DLC + русификаторы) и рисует плитки
   │  2. пользователь нажимает Крест → окно игры → «установить»                      → POST /install {"paths":[...]}
   ▼
служба: enqueue()
   │  • path_allowed()        - только /data/pkg/... и /mnt/usbN/..., расширение .pkg, без ".."
   │  • pkg_read_header()     - заголовок, Content ID, тип пакета, размер, недокачанность
   │  • отбрасывает недокачанные, дубликаты, лишние патчи, backport на прошивке >9
   │  • plan_install()        - порядок: игра → патчи → DLC → русификаторы
   │  • проверка места: сумма размеров против свободного места /user
   │  • bgft_load()           - один раз загружает libSceBgft.sprx и инициализирует BGFT
   │  • кладёт задачи в очередь, будит рабочий поток
   ▼
рабочий поток службы: run_job() по одному пакету
   │  3. bgft_register_local()  - регистрирует задачу «установить локальный файл»   (sceBgft...DownloadRegisterTaskByStorageEx)
   │  4. bgft_start()           - запускает задачу
   │  5. раз в секунду bgft_progress() - читает «передано/всего», ошибку
   │  6. transferred >= length  → «done»; ошибка/нет движения 180 с → «failed»
   ▼
система PS4 сама копирует и устанавливает пакет (значок в «Уведомлениях», игра появляется на главном экране)
   │  7. когда вся пачка закончена без ошибок - всплывающее уведомление «Название / Установлено»
   ▼
приложение раз в ~секунду опрашивает GET /status и рисует окно «Очередь установки»
```

## Ключевая идея
Установку делает **сама система** (BGFT — Background File Transfer, тот же сервис, что ставит игры из PS Store).
Мы лишь передаём ей путь к локальному `.pkg` и следим за ходом. Мы **не** распаковываем PKG и не копируем файлы сами.
Поэтому:
- Content ID берётся из заголовка PKG (36 символов), он нужен как идентификатор задачи;
- путь для BGFT переписывается: `/data/...` → `/user/data/...` (`bgft_path()` в `src/pkg.cpp`), флешки `/mnt/usbN/...` остаются как есть;
- одновременно идёт **одна** установка (очередь последовательная); пока она идёт, новые запросы `/install` принимаются
  (добавляются в очередь), а удаление игр и файлов службой отклоняется кодом 409 `busy`.

## Что нужно, чтобы это работало
- GoldHEN (BinLoader на порту 9090 для отправки службы; payloads.ini для автозапуска).
- Файл `libSceBgft.sprx` в системных папках (есть на штатной прошивке).
- Свободное место в `/user` (проверка грубая: размер файла против свободного места).
- Для флешек: файловая система exFAT/FAT32, смонтированная как `/mnt/usb0`…`/mnt/usb9`.
- Установленные игры могут стоять на внутреннем диске (HDD) или на расширенном хранилище (`/mnt/extN`, EXT). Установку выбирает
  система сама; служба лишь различает их при чтении списка установленных (поле `loc`).

## Чего здесь нет
Скачивание из интернета и торрентов делает не эта служба. Вкладка «Избранное» кладёт magnet-ссылки (`/write_magnet`) или файлы
`<хэш>.magnet` в папку торрент-клиента ps4torrent и читает его процент по `GET 127.0.0.1:8787/status`. Когда файл `.pkg` докачан,
он попадает в «Доступные игры», а дальше всё как в этом документе.
