# Разбор PKG, проверки и порядок установки

Код: `src/pkg.cpp`, `src/pkg.h` (чистый C++, без вызовов консоли, проверяется `tests/test_pkg.cpp` и `tests/test_service.py`).

## 1. Допустимые пути (`path_allowed`)
Установить можно только файл, у которого путь:
- начинается с `/` и не содержит `..` как отдельный компонент;
- заканчивается на `.pkg` (регистр не важен);
- лежит в `/data/pkg/...` **или** в `/mnt/usbN/...`, где `N` — одна или несколько цифр.

Это защита: служба слушает сеть, поэтому произвольные пути отклоняются (ответ `400 bad_path`). Такая же проверка нужна для
`/icon` и `/delete_files`.

## 2. Заголовок PKG (`pkg_parse_header`)
Все числа — big-endian. Берётся первый 4 КиБ файла.

| Смещение | Размер | Поле |
|---------|--------|------|
| `0x00` | 4 | сигнатура `7F 43 4E 54` («\x7FCNT») |
| `0x10` | 4 | число записей в таблице файлов PKG |
| `0x18` | 4 | смещение таблицы файлов PKG |
| `0x40` | `0x24` (36) | **Content ID**, ASCII, например `UP0006-CUSA15080_00-STARWARSQUADRONS` |
| `0x74` | 4 | тип содержимого (`content_type`) |
| `0x78` | 4 | флаги (`flags`) |
| `0x430` | 8 | `pkg_size` — полный размер пакета по заголовку |

Проверка Content ID: длина 36, дефисы на позициях 6 и 19, символы только `A-Z 0-9 - _`. Title ID — подстрока `content_id[7..16)`
(например `CUSA15080`).

Тип содержимого:

| Значение | Что это | `kind` |
|---------|---------|--------|
| `0x1A` | игра / патч / ремастер | `game`, а если в `flags` есть бит патча — `patch` |
| `0x1B` | дополнение с данными | `dlc` |
| `0x1C` | дополнение без данных | `dlc_nodata` |
| `0x1E` | дельта-патч | `delta_patch` |
| другое | не поддерживается (`422 bad_pkg`) | |

Флаг патча: `flags & (0x00100000 | 0x40000000 | 0x41000000 | 0x60000000)` ненулевой → `is_patch`.

## 3. param.sfo и значок внутри PKG
Таблица файлов PKG: записи по 32 байта, поля big-endian: `+0` id записи, `+16` смещение, `+20` размер.
- запись **`0x1000`** — `param.sfo`: из него читаются `TITLE`, `APP_VER` (запасной `VERSION`), версия `01.04` → `ver_num = 104`;
- запись **`0x1200`** — `icon0.png` (для плиток и окон, ограничение 4 МиБ).
Формат PSF: сигнатура `00 50 53 46`, little-endian, `key_off @8`, `data_off @12`, `count @16`, записи по 16 байт с `key_off16 @0`,
`len @4`, `data_off @12`.

## 4. Признаки по имени файла и папки (`pkg_apply_name_tags`)
Имя файла (без расширения) и имя ближайшей папки режутся на слова (буквы, цифры, кириллица), регистр не важен:
- `backport` — слова `backport`, `backports`, `bp` или подряд `back port`;
- `rus` — `rus`, `ru`, `russian`, `rusifikator`, `русификатор`, `рус`, `русский`, `русская`;
- `dlc_name` — `dlc`, `dlcs`, `expansion`, `addon`.

## 5. Недокачанные файлы (`PkgInfo::incomplete()`)
Пакет считается недокачанным (и НЕ ставится, `skipped` с причиной `incomplete`), если выполняется любое:
1. `file_size < pkg_size` — файл на диске короче, чем записано в заголовке (обычная загрузка, оборванная посередине);
2. `zero_blocks >= 2` — торрент-клиент создаёт файл сразу полного размера, а непришедшие куски остаются нулями.
   `pkg_probe_zeros()` читает **49 проб по 4 КиБ** (48 мест, равномерно распределённых по файлу, без самого начала, и последняя —
   самый конец) и считает, сколько из них целиком нулевые. Файлы меньше 8 МиБ не проверяются. Результат кэшируется по
   `(путь, размер, mtime)`.

Слабое место: если не докачана малая часть файла, пробы могут её пропустить (процент приблизительный). Магазин не считает
процент скачанного сам — только метка «НЕ ДОКАЧАНО».

## 6. Сканирование (`scan_packages`)
Корни: `/data/pkg` и `/mnt/usb0` … `/mnt/usb9`. Обход вглубь до 6 уровней, до 3000 файлов. Пропускаются папки, начинающиеся с `.`,
`$RECYCLE.BIN`, `System Volume Information`, `disc`. Файл, у которого заголовок не разобрался, отвергается (в журнале причина).

## 7. Планирование установки (`plan_install`)
Вход: список проверенных пакетов одной пачки. Выход: порядок установки и список пропущенных.

1. **Backport** пропускается, если прошивка выше 9 или неизвестна (`fw_major < 0 || > 9`).
2. Из нескольких **обычных патчей** одной игры (`kind == patch`) с известной версией остаётся самый новый, остальные
   пропускаются («есть более новый патч»).
3. Порядок игр: по «якорю» — размер самого большого основного файла игры (основной важнее любого другого файла), от большего к меньшему.
4. Внутри одной игры (`rank_of`): **0 игра → 1 патчи → 2 DLC → 3 русификаторы**. Патчи по возрастанию версии; внутри остальных групп от
   большего файла к меньшему; при равенстве — по пути.
   - DLC — `kind` `dlc`/`dlc_nodata` либо слово DLC в имени;
   - русификатор — файл с пометкой `rus`, у которого есть основа в той же пачке или который не `game`;
   - патч — `is_patch` или `delta_patch`.

Причина: патч нельзя ставить до его игры, а DLC и русификатор — до патчей (иначе система откажет или перезапишет).

## 8. Дубликаты
- Одинаковые пути в одном запросе игнорируются.
- Копии одного и того же пакета (одинаковые Content ID + тип + размер) на диске и на флешке ставятся один раз (в приложении
  то же правило при группировке плиток).
- Если задача уже стоит в очереди/идёт, повторно не добавляется.

## 9. Проверка места (`enqueue`)
`need` = сумма `file_size` всех пакетов, которые будут установлены, + остаток по уже идущей очереди. Сравнивается со свободным
местом `/user` (`statfs`). Если `free < need` → `409 no_space` с полями `need` и `free`.
Это **грубая** защита: реальный размер установленной игры может отличаться от размера PKG (на консоли для всех случаев не проверено).
